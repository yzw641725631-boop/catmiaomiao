# 视觉上传失败定位 v1.0

日期：2026-10-28，Asia/Shanghai。项目：openmaus-assistant。范围：用户刚提交的浏览器检索工作与 `deepseek-v4.1-flash-vision-exp` 报错调查。本轮只读诊断，未修改应用代码、模型设置、服务器部署或账号数据，未重放用户工作，未启动任何续签执行端。

## 当前结论

视觉模型在该任务窗口中多次成功完成请求，两次失败发生在美国 Whale 网关向上游上传截图的鉴权阶段。两次原因不同：一次账号令牌无效，一次触发上游正常网页登录验证。网关均返回 HTTP 500 / `Failed to upload inline file.`，本机统一显示 `VISION_IMAGE_UPLOAD_FAILED`，因而前台无法区分。

不是全部账号失效或模型始终不可用的证据；当前图片链路仍不稳定，原任务尚未核实完成。

- 读取本机 `/companion/info`、该 thread 的原生消息和 `runtime/logs/model-requests.jsonl`，按时间对齐任务错误与模型诊断。

- 美国容器当时显示 healthy、运行约六天；容器健康不代表上游账号有效。

## 代码链路与边界

`adapters/reachai.mjs` 遇到图片消息时转交 `adapters/vision.mjs`；`adapters/vision-transport.py` 经现有 SSH 链路调用美国网关 `127.0.0.1:5001/v1/chat/completions`，模型固定为 `deepseek-v4.1-flash-vision-exp`。

Python 适配当前依据网关错误正文 `Failed to upload inline file.` 分类，不能获取被网关包装掉的账号失效/网页验证差异。当前错误发生在上游文件上传阶段，不能写成图像理解或推理质量错误，也没有证据证明改提示词、减少文字上下文或重启本地服务可以修复。

10-23 历史验收曾定位部分账号 invalid token；本轮新增确认最近一次失败实际为 HTTP 202 网页验证，不能套用旧结论解释全部 500。
