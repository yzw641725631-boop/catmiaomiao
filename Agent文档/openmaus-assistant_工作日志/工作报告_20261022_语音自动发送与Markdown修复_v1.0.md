# 语音自动发送与 Markdown 修复工作报告 v1.0

日期：2026-10-22（Asia/Shanghai）。项目：openmaus-assistant。范围：用户反馈的停顿不发送、语音无回复、Markdown 原样显示；保留已确认布局。

## 结果与原因

| 问题 | 原因 | 当前行为 |
|---|---|---|
| 说完后不自动发送 | 原录音只有手动结束、识别结果只进草稿 | VoiceCapture + VoiceActivity 检测有效语音后约 1.2 秒静音，结束录音并等待 ASR 完整回执，再发送一次；取消/无语音不发，已有草稿保留 |
| 语音没有对应回复/播报 | 识别结果未直接发送；朗读只判断新增消息 ID，漏掉同 ID 的终态更新；实时中继可能吞掉同 segment 的 end | 发送与录音状态解耦；按 sendId 和原生 requestMessageId 匹配成功终态，语音自动播报一次；end 确认与转写内容分别去重 |
| 表格等显示为 Markdown 文本 | 未启用 GFM，流式使用原始文本 | MessageMarkdown 统一终态/流式渲染，react-markdown + remark-gfm 4.0.1，表格内部横向滚动；代码块按原文显示源码，安全下载和链接规则保留 |

Web Audio/AudioWorklet 提供 PCM 和本地能量 VAD；整段模式使用 MediaRecorder，实时模式为 16k PCM WebSocket。ReachAI 负责 ASR/TTS，原生 OpenMausBot 负责 LLM 和会话。点击一次录一句话，不自动常开麦克风或接着录音。打字回复的朗读开关与语音回复自动播报分别控制。服务暂未启动时前台初始连接会重试。
