## 已确认结论

1. 当前不能动态创建小助理/Skills，首先是本地工具 allowlist、HTTP 白名单和固定 helperIds 的接入限制。固定上游已经包含 `create_bot`、`skills_list`、`skill_manage` 和技能导入。仅放开工具名仍不能覆盖动态团队所需的身份、作用域和消息投影。
2. 当前服务是 Node harness，缺 Electron CUA host、驱动和屏幕接管入口；上游固定版本已有 Windows 0.28.2 接线。Computer Use 不是当前已接通功能。
3. 已通过 web 工具查阅 Grok Bot 官方指南、Muse 发布与设计文章及候选 GitHub。GitHub API 对 10 个仓库取得提交、推送时间、归档、根许可和许可哈希，均无请求错误。来源快照：`projects/openmaus-assistant/evidence/product-research-20261023/source-audit-2026-10-22T17-35-36.661Z.json`。
4. 推荐沿用原生创建/技能/MCP 管理，电脑优先原生 Cua Driver，浏览器备选 Playwright MCP，聊天评估 assistant-ui，交互成果评估 MCP-UI / MCP Apps。Tool UI 已归档，应限于挑选组件源码；UI-TARS/OpenClaw 为完整执行系统，不直接叠加第二个主循环。Cua Spaces 为 FSL，MCP Apps 许可处于 MIT/Apache 过渡，未误写为整个仓库单一许可。
5. 查阅当前真实页面证据和上游电脑面板截图。Muse 官网已实际打开，截图核对到文章和富成果示例局部；浏览器远程页面 AX 读取/合并截图多次超时，未将其写成登录后完整交互实测。Grok 公开指南图部分加载失败，设计结论依据可读取官方说明与源仓库。未绕过任何浏览器安全页。
6. “Grove Vault / Vault”和“Chávez”尚未核实。已询问后者是否为 Skills / 创建小助理；未收到回复前同时审计，不擅自确定为新产品或访问其他项目。
