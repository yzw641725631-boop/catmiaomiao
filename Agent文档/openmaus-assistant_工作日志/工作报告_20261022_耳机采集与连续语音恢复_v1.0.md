# 耳机采集与连续语音恢复工作报告 v1.0

日期：2026-10-22（Asia/Shanghai）。项目：openmaus-assistant。

用户反馈说话后“没有听到清晰的说话声”，确认使用耳机麦克风；随后明确要求停顿 2 秒、连续语音直到“转为打字”，并排查 502。本次按明确交互要求实现，不重做人物/布局、不改其他项目或云端配置。

新增本地设备选择与音量测试，采集使用原生采样率、请求自动增益、降低过高的本地 VAD 门槛并保留非零输入的 ASR 兜底。实际页面收到 USB 麦克风音频；用户确认音量条变化，也确认单轮语音自动发送并收到回复。未保存真人原始录音。

提前收句另有确定原因：实时中继设置 800ms，客户端收到 VAD final 就立即结束，绕过本地停顿。现本地和服务端参数均为 2000ms，提前分句只累计。ContinuousVoice 控制器负责倾听→发送→本次成功回复播报→继续倾听；静音不发空聊天，模型失败后继续听；转打字/设置暂停会取消采集，迟到结果不能重开麦。后台工作不阻塞下一句。当前轮流说话，非全双工。

502 来自模型链路错误包装；直连比较中当前 DeepSeek 3/3 成功，原 agens 有 39.68 秒慢响应和 45 秒探针超时。开发保留用户当前 DeepSeek 选择。增加最多两次、仅在首次输出前的临时模型重试，已出现文字/工具调用后不重播任务；增加不含正文和凭证的请求元数据日志。原生主助理带实际上下文的验证成功，总约 10.35 秒。云端具体内部故障不能仅凭这些证据断言已根治。

最新主助理与文档助理失败已定位：当前 DeepSeek 上游 HTTP 503，ReachAI 服务端日志给出 `upstream_web_verification`，即上游要求网页验证、本次账号尝试耗尽。主助理与短上下文的文档助理均在输出前失败，不能归因于麦克风或仅仅上下文过长。旧 502 包装已修正：503 保持 503，已知网页验证错误映射为 `MODEL_UPSTREAM_WEB_VERIFICATION`，显示更换模型/处理上游验证的提示，且不自动重试这类错误；普通临时错误仍有最多两次重试。没有尝试绕过网页验证或改动线上账号池。

原生派工请求会为后续恢复保留 `requestPending:true`，即使本轮已有明确的 `tool.terminal && ok:false` 模型错误。VoiceReplies 现以同一 requestMessageId 的最新终态回执结束语音等待；不把较早的“已派工”当成成功答复，不修改内核历史或自动重发任务。对应失败会提示并自动续听，迟到的旧回复不播报。

重启后当前主助理带 43 条上下文、4 个工具定义、35723 字节请求约 11.78 秒成功返回；模型自身约 10.63 秒。此次成功只证明该次恢复，网页验证导致的服务波动没有根治。当前保留用户选择的 DeepSeek，已向用户提供临时切换既有 agens 的选择，未获回复前不替换；agens 先前有慢响应/超时，不能承诺其稳定性。

完整技术说明与证据路径见 `projects/openmaus-assistant/docs/连续语音与模型错误恢复_v1.0.md`。当前全量 `evidence/app-checks-2026-10-22T14-07-46-020Z/`：类型、62 项测试、构建全部通过，0 失败、0 跳过。此前 48 项阶段与首轮定向测试中因采样率测试桩/等待长度调整出现的失败均未删除；最终结果以上述全量为准。

浏览器已加载新版，连续模式显示“说完停顿 2 秒自动发送”“转为打字”，实际麦克风音量可见。已邀请用户测试连续两轮；用户随后反馈主助理与文档助理均失败；本次已核实为模型上游 503/网页验证，未将该反馈误记成连续两轮成功。新版 22:13 主助理请求成功、连续倾听开启，截图 continuous-voice-delivery.jpg；原始失败与旧 502 历史保留。独立 G5 未终签、G7 未申请；历史汇总准确性缺口保留。全局 main.md、上游源码、其他项目索引保持不变。
