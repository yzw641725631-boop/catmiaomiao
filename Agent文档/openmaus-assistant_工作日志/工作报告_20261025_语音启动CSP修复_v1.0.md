# 语音启动 CSP 修复工作报告 v1.0

日期：2026-10-25，Asia/Shanghai。项目：openmaus-assistant。沿既有本地 G2/G4 修订，独立 G5 未终签，G7 未申请。

## 原因与修复

用户说“启动错误”，补充为“点击语音报错”。5217 服务及主对话正常，正式页面点击麦克风可重现：`no available backend found`，浏览器明确记录 WebAssembly 编译被 `script-src 'self'` 阻止。本地 Silero/ONNX 在麦克风取得后、ASR 连接之前初始化失败。此前 Vite 页面上的模型推理检查没有覆盖正式服务的 CSP，因此不能作为正式语音入口通过的证明。

`adapters/server.mjs` 的正式页面 `script-src` 增加 `wasm-unsafe-eval`，其余来源、内联脚本、JavaScript eval、iframe 和对象限制保持；没有关闭 CSP，也没有增加远程脚本来源。规范依据：[W3C CSP Level 3](https://www.w3.org/TR/CSP/)、[MDN script-src](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src)。`app/src/speechGate.ts` 统一覆盖 import、新建模型和启动阶段的失败与资源释放，前台显示中文可操作提示，原始错误保留于 cause。

## 验证与恢复

- 新增真实 HTTP 服务契约检查：正式 HTML 提供 WASM 编译许可，JavaScript eval/inline、跨来源连接和嵌入限制仍保持；本地 WASM 的 MIME 与文件头、worklet 的 MIME 均符合预期。
- [完整检查](../../evidence/app-checks-2026-10-25T13-11-29-433Z/report.json)：类型、109/109 测试和生产构建通过。
- 先确认没有正在执行/等待小助理的工作，再正常停止和重启本项目后台服务；[前后记录](../../evidence/voice-startup-20261025/after.json)确认主助理、原主对话、3 位成员、模型设置、本领配置及 main.md 哈希保持。
- 在同一个正式 5217 页面刷新后点击麦克风：本地模型加载、实时识别连接、AudioWorklet 采集进入 `listening`，音量表显示收到声音，运行 25 秒无新的初始化错误。关闭为打字后再次开启，仍进入 `listening`，新增错误列表为空。见[浏览器回执](../../evidence/voice-startup-20261025/browser-acceptance.json)及[界面截图](../../evidence/voice-startup-20261025/voice-listening.png)。测试结束已关闭麦克风。

本轮验证语音启动和重新开启，不替代用户实际讲话后的识别、回复、TTS 和长时间对话验收；没有声称上游稳定性或全双工已通过。旧错误控制台记录保留，复验按刷新后时间过滤。未改上游源码或外部服务配置。
