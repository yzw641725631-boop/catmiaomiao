# 工作报告：动态小助理创建与派工接通 v1.0

日期：2026-10-23（Asia/Shanghai）。项目：openmaus-assistant。用户澄清此前口述能力是“创建小助理”。沿用已批准的原生多助理方案、持续推进授权和 G2/G4；没有把小助理理解成 Codex 开发代理，也没有启动开发子代理。

## 结果与变更

已接通模型原生 create_bot 与手动创建两条入口、动态团队登记、成员实际派工/回报、工作文件工具归属和重启保持。Chief 只增加创建工具，小助理沿用受限工具及当前模型，无电脑/浏览器/任意终端权限。主因不是底座没有创建能力，而是此前 allowlist、固定 helperIds 和 IPC/服务成员检查把已有链路截断。

新增 adapters/team.mjs、受摘要保护的 Store 加载钩子、同源 POST /companion/team/specialists、动态 refreshTeam、SSE 成员刷新。前台新增团队抽屉、可读的原生创建回执、职责表单和安排工作入口。保留已确认的人物/书房，成员用分隔行，常驻区域只显示最近两名。

初测发现原生本地所有者创建通常直接 applied，测试已按实际版本修正，没有另造一次确认；严格 native schema 不接收 autoApprove/connectorTools 的创建字段，适配已修正。UI 实测还修正了创建结束焦点丢到背景，以及弹窗关闭时抢回任务输入焦点；任务草稿不再显示技术 bot ID。
