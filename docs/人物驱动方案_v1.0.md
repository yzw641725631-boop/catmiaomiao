# 人物驱动方案 v1.0

版本：v1.0。日期：2026-10-21。状态：方案待评审；未下载驱动模型，未测本机人物推理。

## 推荐路线

保留已批准的成年女性外观，先制作可分层的人物与书房资产，使用独立 AvatarDriver 表达倾听、思考和播报状态。照片口型以 MuseTalk 1.5 做小样验证；通过外观、速度和打断测试后才进入默认体验。首版功能开发可以使用同一人物静态图或已制作的待机动作，但必须如实区分“语音可用”与“实时口型可用”。

当前批准的是完整界面效果图，人物和背景尚未分层，也没有骨骼、表情集或动画。不能直接把这张图当作已经绑定好的 3D 模型。

## 候选对比

| 方案 | 官方输入/能力 | 对本项目的判断 |
|---|---|---|
| 分层照片 + 预制短动作 | 人物层、背景层、动作素材；前台合成 | 最容易保持已批准外观；用于界面和状态验证，未制作素材前不能宣称会眨眼或动嘴 |
| [MuseTalk](https://github.com/TMElyralab/MuseTalk) | 音频驱动口型，主要处理 256×256 面部区域，支持中文；官方 30fps+ 条件为 Tesla V100 | 照片质感口型首选 POC；本机速度、嘴部稳定性和连续播放待测；不是完整身体/眼神驱动 |
| [LivePortrait](https://github.com/KlingAIResearch/LivePortrait) | 图片/视频 + 驱动视频或 motion template | 可试做待机、转头或眨眼短片；本身不是直接音频口型服务，两模型串联不视为已解决 |
| [TalkingHead](https://github.com/met4citizen/TalkingHead) | 浏览器 3D，需要 GLB、兼容骨骼与 ARKit/Oculus viseme blendshapes | 适合交互动画，但需要额外建模才能匹配当前人物；不作为未经确认的替换形象。中文须接外部 viseme 或音频驱动模块 |

MuseTalk 建议 Python 3.10、相应 CUDA/PyTorch 和 FFmpeg；采用单独环境，固定版本，不升级系统 Python、显卡驱动或其他项目依赖。[安装说明](https://github.com/TMElyralab/MuseTalk#installation)。其代码/模型许可说明见 [LICENSE](https://github.com/TMElyralab/MuseTalk/blob/main/LICENSE)。LivePortrait 代码为 MIT，但仓库声明 InsightFace 预训练模型仅限非商业研究；当前个人试验也应保留记录，若未来商业化需替换受限组件。[许可说明](https://github.com/KlingAIResearch/LivePortrait/blob/main/LICENSE)。

## 资产制作规范

1. 从批准图派生无 UI 的书房背景，以及同脸、同发型、同衣服、同左侧光源的独立人物。图像编辑使用图像模型，保留原始批准图。
2. 人物在 1080p 参考画布中居中，面部、手和椅子完整；为头部动作留余量，右侧保留时间线空间。抠图边缘检查头发、袖口、椅背遮挡和接地阴影。
3. 需要可循环待机动作时，只做幅度很小的呼吸、眨眼与视线变化；人物尺度、背景和构图固定。素材重复或表情过度时回到静态清晰版本。
4. 静态、待机、口型资产使用同一坐标和颜色基准。不能靠切换另一张脸来表示状态。
5. 背景和角色图只负责呈现，文字、日志和按钮全部由 UI 实现。

以上是下一阶段制作任务；本轮仅保存原概念图，未生成分层资产或动作片。

## 驱动接口草案

`AvatarDriver` 在前台只接收可展示状态，不接触模型密钥和工具参数：

```ts
type AvatarState = 'idle' | 'listening' | 'thinking' | 'speaking' | 'attention' | 'offline';
interface AvatarDriver {
  load(assetManifest: string): Promise<void>;
  setState(state: AvatarState): void;
  enqueueSpeech(chunk: { utteranceId: string; generation: number; audioRef: string; caption: string }): Promise<void>;
  interruptSpeech(generation: number): void;
  setReducedMotion(enabled: boolean): void;
  dispose(): void;
}
```

音频播放时钟为口型与字幕的共同时间源。字幕不能按 token 到达时间伪装口型。用户打断后递增 generation，取消旧合成、丢弃旧音频/视频片段并闭嘴；后台 task 是否停止由另一个明确动作决定。

照片推理服务是可关闭的本地 sidecar，只绑定 loopback，使用每次启动的能力令牌；由桌面主进程启动与回收。前台通过同源受控入口拿片段。超时、OOM 或服务退出时回退到同一人物的静态/待机呈现，不影响文字和后台任务。

## POC 验收与决策

测试素材：同一批准人物，中文 5 秒、15 秒和 60 秒音频；静音、句中停顿、多段连接和连续 10 次打断。音频使用明确可用的测试声音，不预设用户已经配置厂商。

| 检查 | 目标 / 决策规则 |
|---|---|
| 外观 | 人脸、发型、衣服和光照一致；嘴边、牙齿、头发和肩部无持续抖动；保留小样供用户看 |
| 合成速度 | 记录预处理耗时、峰值显存、稳态 fps、RTF=生成耗时/音频时长；目标播放 25fps 且 RTF≤1，不能只报最快一次 |
| 音画同步 | 使用同一音频时钟，稳态偏差目标≤120ms，跨句不累计漂移 |
| 起播 | 分别测模型首 token、TTS 首音频和 avatar 首帧；已预热的口型附加等待目标≤500ms |
| 打断 | 前台声音停止目标≤150ms，画面收口目标≤250ms，旧片段不得重新播放 |
| 失败 | OOM/退出/断开后仍能继续文字与任务；重启不能重放已取消句子 |
| 结论 | 达标才推荐本机实时照片口型；未达标记录实测，保留清晰人物+语音体验，后续另评估更轻方案或远端推理 |

这些数值是设计目标，不是本轮测量结果。不会为了追求口型，让说话先等待整段视频渲染完成。
