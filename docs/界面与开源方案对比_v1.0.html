个人助理：界面为什么不好看，可以借谁，要不要换底座

openmaus-assistant 调研，2026 年 10 月 31 日。代码与截图取自本机项目目录；开源项目的星数、许可和更新时间为当天 GitHub 与官网所见。

底座不用换，但要解决升级被锁死的问题。OpenMausBot 自己的 README 写的就是“开源 Grok Bot 替代”，Apache-2.0，能力不比 OpenClaw、Rakazo 少。真正的问题是适配层在加载时改写了 3 个上游文件，还直接引用了 9 个上游内部模块，所以一直停在 v0.1.121，上游的新版本用不上。

不好看主要是做出来的东西偏离了效果图。和已批准的效果图比，右侧面板大了约 2.3 倍，输入框压在人物身上，顶栏有三种形状的按钮。样式里有 402 种不同色值、17 种像素字号、41 处 !important，每一轮修改都是在上面再叠一层覆盖。

最该借的是你底座自带的界面。OpenMausBot 上游已经有审批卡、提问卡、电脑面板、例行日历这些 React 组件，带中文和浅色主题。人物陪伴方向可以借 Lobe Vidol 的构图、TalkingHead 的动态和 ElevenLabs 的语音球。工作区方向可以借 Muse 的目标页和状态视图，以及 Eigent 右栏的分组方式。

工作中补充一句、另开一个任务：底座已经支持插话和另开线程，但补充送不到已经交出去的工作，主助理也不知道自己开出去的工作现在什么状态。见第 5 节。

批准的效果图

右上一张小卡，底部居中一条细输入条，左下只有图标。人物和书房占画面的大部分。

  1. 右侧面板占画面 28.7%，效果图里是 12.7%，大了约 2.3 倍，把场景和人物挤到左边三分之二。效果图那张卡只有两条消息，真实面板确实需要滚动区，但不必占满整列高度。
  2. 输入框从细胶囊变成了双层厚卡。效果图里它居中、在人物膝盖下方；现在加了工具行和快捷键提示，靠左放，挡住了人物的手和腿。
  3. 小助理多了一张磨砂卡片，带标题、“添加”和“查看”链接。效果图里只有图标和两行字，画面里因此又多出一块面板。
  4. 字幕和“纯净视图”按钮都压在人物身上。效果图里字幕是脸下方居中的一行字，按钮在右下角；现在字幕是深色胶囊，按钮落在扶手上。
  5. 顶栏一排有三种按钮形状：3 个方形文字按钮、1 个状态胶囊、3 个圆形图标按钮。效果图的顶栏只有左上角的标志。
  6. 小字太多。日期、筛选计数、状态都在 10–11px。全站 CSS 共 364 处字号声明，其中 9–11px 有 156 处，占 43%。9px 有 12 处，比设计规范里最小的辅助字号（10px）还小。

两个方向可以借谁

左列保留书房和人物，右列是 Muse / Grok Bot 那种工作区。每张图下面标了结论。远程截图需要联网才显示，点图可以放大。

直接复用借界面、组件或形象只参考或待实测慎用

人物陪伴：留在书房里，让她活起来

这一类开源项目形象和语音做得好，但都没有派工、审批、文件账本这些你已经接通的能力，只适合借形象层和界面。

工作区：像 Muse / Grok Bot 那样把工作摆出来

两个商业产品都没有开源，只能当交互蓝本。它们和你的差距不在能力，而在目标、动态、审批、电脑画面、成果这些对象有没有自己的视图。

两种方向可以合成一个。平时是书房和她，形象下面一行字写着她在做什么，这是 Muse 的做法。点她或者说“看看进度”，右侧展开成工作区，里面用上游现成的审批、电脑、目标组件。陪伴和干活就不用挤在同一屏里。选哪种由你定，第 6 节的前三步两种方向都要做。

3

要不要换底座

按你说的，把“整体换掉”也认真比了一遍。下表只列有可能替代的几个，第 2 节里只适合借界面的没有放进来。

项目许可规模与活跃和你要的能力对得上多少换过来要付的代价结论

为什么说升级被锁死。adapters/workspace-hook.mjs 在加载时改写 3 个上游源文件（server/index.ts、server/store.ts、server/drivers/chat-mcp-tools.ts），共 12 处字符串替换，每个文件都用 SHA-256 锁定。另外有 11 个 adapters 文件直接引用 9 个上游内部模块，其中 server/testing/ports.ts 和 server/testing/cleanup.ts 是上游的测试工具。上游任何一处改动都会让启动报错。这是有意做的安全设计，代价是一直停在 v0.1.121，上游 10-30 之后的修复你都拿不到。

换底座解决不了这个问题。换成 OpenClaw 这类更新更快的项目，照样要写适配层，照样会锁版本。真正要定的是升级办法：先把改写点压到最少；上游 LICENSING.md 写明“任何开源用户都可能想要的东西进 core，走公开 PR”，派工范围、例行工具策略这类钩子可以提成上游的扩展点；剩下的改写点每次升级按固定清单核对。

4

你的代码

前端看 app/src 的 42 个文件，架构看 adapters/ 和它怎么接上游。数字都是本地脚本统计出来的。

402

样式里不同的色值。445 次使用里几乎每次都是新挑的颜色；设计规范和后来的修订合计列了不到 30 个。

17种

像素字号，从 9px 到 28px。规范里列的不到 10 种。

26种

圆角写法。规范定的是 8 / 12 / 20px，修订后合计 7 种。

41处

!important。另有 75 个类选择器在两个以上 CSS 文件里重复定义。

为什么会这样

样式是一轮一轮叠上去的。main.tsx 依次加载 6 个 CSS 文件，共 87KB，后加的覆盖先加的，没有哪一处说了算。.timeline-panel 这类选择器在 4 个文件里都有定义。design-tokens.md 在原始表格前面叠了三段带日期的修订，其中两段都写着冲突时以本段为准。

界面是用替换脚本改的。evidence/apply-interaction-ui.mjs 这类脚本按锚点字符串改写 App.tsx。结果 App.tsx 52.5KB 只有 388 行，最长一行 2,046 个字符，里面有 34 个 useState；style.css 30KB 只有 45 行，最长一行 5,780 个字符。人和下一个 Agent 都很难整体读懂，只能继续打补丁。

人物是静态图。分层图片，没有眨眼、呼吸和口型。陪伴感全靠一行字幕撑着，周围的面板就显得更重。

和上游界面比

上游界面的规模大一个数量级。上游 src/ 有 674 个 TS/TSX 文件，约 5.2MB（不含测试），用 Tailwind 4 和统一的设计 token，有浅色主题和 zh / zh-tw 语言包。你的 app/src 是 42 个文件，约 364KB，把其中的对话、审批、电脑、目标、例行又做了一遍。

但上游界面不能直接拿来用。它是 Telegram 式的三栏聊天软件，没有书房和人物；组件依赖上游自己的 store、i18n 和功能开关。要用就整层接入它的状态层，再把书房做成其中一个视图，不能把组件文件一个个拷过来。

做得好的地方

只有一套 Agent 内核。没有在旁边再造第二个主循环，派工、记忆、审批都走原生。

改动集中、出错就报。上游目录本身没有被修改，改动集中在 adapters，上游一变就启动失败，不会悄悄跑错。

安全边界清楚。凭证只在服务端，浏览器拿不到；转发有白名单和 owner token；文件有逐次授权、账本和 hash 校验。app/tests 有 32 个测试文件，10-25 的完整检查 116 项通过。

风险

升级被锁死，见第 3 节。

日常运行借用了上游的测试脚手架。runtime.mjs 用 scripts/control-omb.ts 的 verificationServerEnvironment 和 server/testing/ports.ts 启动日常服务。这些不是上游承诺稳定的接口，上游改自己的测试工具也会波及这里。

没有版本管理。agent_project 和 openmaus-assistant 都不是 git 仓库。多个 Agent 用替换脚本改代码，出了问题只能翻归档目录，没有 diff，也没法一键回退。

evidence/ 有 1,618 项。其中 workspace-contract-* 458 个、services-contract-* 218 个测试临时目录没有清理。这次查一遍截图，find 命令跑了 120 秒超时。

5

工作中补充一句、另开一个任务

你要的是：她正在干活时你再补一句，她接着做；你说的如果是另一件事，就另开一个去做。我按代码查了三种情况现在实际怎么走。

情况现在实际怎么走结果缺口
她正在回你时
补一句		本地服务照常转给上游。上游发现主对话这一轮还没结束，就把这句话插进去：等手上这批工具调用做完，下一步思考前让模型看到（上游 server/index.ts 的 acceptDirectSend，drivers/openai-chat.ts 的 steer）。带图片的补充插不进，改为排队。基本能用页面只认“已排队”一种回执，插进去了不提示。每句补充都会被本地服务附上一千多字的固定说明、实时状态和能力清单（adapters/runtime.mjs 451–456 行），一句短补充被埋在里面。
工作已经交出去后
补一句		补充进的是主对话，不是那项工作。主助理看到的实时状态只列小助理各有几项在跑，不列她自己开出去的工作（liveWorkNote 只遍历小助理）。她也没有“给某项工作补一句”的工具：assistant_start_work 每次都新开一项；上游的 list_threads、start_thread 不在她的工具范围里（adapters/team.mjs 的 CHIEF_TOOL_SCOPE）。工作详情页没有输入框。持续目标执行中补充会被直接拒绝（adapters/native-goals.mjs 返回 409“这项目标正在执行”）。到不了补充送不到正在做的那项工作。主助理只能再开一项重复的新工作，或者嘴上答应。你说的问题主要出在这里。
说的是另一件事主助理调用 assistant_start_work 新开一项独立工作，再在里面派小助理。10-23 验收过“工作还没结束时，主对话照样回复”。能用主助理只能从对话历史里看到自己开过哪些工作，看不到它们现在还在不在做，所以不容易分清这句是补充还是新任务。新开的工作不在左下小助理里显示，只在动态列表里。

别人怎么做

产品工作中再发消息另开任务
Meta Muse官方设计文章原话：“你可以中断它或同时发送多个任务，而无需等待它回复上一个任务。”复杂主题另开“旁聊”，保持独立上下文。消息可能不按顺序到，所以用气泡分开每个想法。
Grok Bot官方指南只写了三种对话方式：聊天、例行与触发、bot 之间互相发消息。工作中补充怎么处理没有写【未找到原文】。专家 bot 加群聊，一个 bot 可以去问另一个。
OpenClaw/queue 有四种模式，默认 steer：把消息插进正在跑的那一轮，工具执行中也行。followup 排到下一轮，collect 把几条合成一条，interrupt 打断当前、改跑最新一条。可以派生子代理，默认每个会话最多 8 个并行。
OpenMausBot 上游
你的底座		同一线程忙时先插，插不进再排队（server/admission.ts 的 direct-busy）。有“把排队的消息立刻插进去”的接口（/api/bots/:id/queue/:id/steer）和对应的 ComposerQueuedMessages 组件。start_thread 在自己身上另开一条独立工作；每个 bot 默认最多 3 条线程同时在跑。

结论

底座已经会插话，也会另开一条。缺的是你这一层：补充送不到正在做的那项工作，主助理也不知道自己开出去的工作现在是什么状态。这些改动都在 adapters 和 app 里，不用碰上游，也不增加第 3 节说的升级负担。

“另开一个子代理”有两种做法。一种是在主助理身上另开一条工作线程，相当于她的分身，做完就结束；另一种是用 create_bot 建一个长期小助理。临时任务适合前一种，不然团队会越建越多。现在的 assistant_start_work 走的就是前一种。

建议怎么改

给主助理加一个“补充到工作”的工具。参数是工作编号和补充内容。本地服务把这句话发进那项工作的线程，由上游决定插入还是排队，回执写明是哪一种。持续目标执行中的补充也改成排队，不再直接拒绝。

让她看得到自己手上的工作。实时状态里列出她开着的工作：编号、标题、在跑、等你还是已结束。分不清时用选项卡问一句：“补充到《××》，还是另开一项？”

工作详情页加输入框。在那里打字就直接发进这项工作，不靠模型判断。

回执要让你看见。页面区分三种：已插进当前回复、排在后面、新开了一项工作。她正在回你时，补充只发原话，不再附那一千多字的说明。新开的工作在左下以临时小助理显示，做完收起。

6

建议的顺序

前三步不管选哪个方向都要做。第 2 步做完、看到新首页之后，再决定第 4、5 步谁先。右边的“小 / 中 / 大”只是相对大小，不是人天估算。所有改动照常走项目门控，这一页只是调研，没有改任何代码和运行数据。

  1. 先打地基

    建 git 仓库（upstream/ 已在 .gitignore 里）。引入 Tailwind 4 和一份 token 文件，替换 6 个叠加的 CSS。拆开 App.tsx，停止用替换脚本改界面。evidence/ 里的测试临时目录先归档再清理，以后测试跑完自己删。

    中不改外观

  2. 按效果图重排首页

    右侧面板收成浮动卡片，输入框改回居中细胶囊，字幕挪到人物下方，小助理去掉卡片，顶栏按钮收进一个菜单，加 ElevenLabs 那种语音球表示在听、在想、在说。改完和效果图并排截图对比。

    小效果最明显

  3. 补充送得到、新任务分得清

    按第 5 节：加“补充到工作”的工具，实时状态列出她开着的工作，工作详情页加输入框，页面区分插入、排队、新开三种回执，持续目标执行中改为排队补充。只改 adapters 和 app。

    中两个方向都要

  4. 工作视图换成上游组件

    审批卡、提问卡、电脑面板、目标卡、例行日历改用上游 src/components，接它的 store，统一浅色 token。右栏按 Muse 和 Eigent 的方式分成动态、目标、成果几块。

    大工作区方向

  5. 让她动起来

    先做不需要模型的：待机呼吸、眨眼、说话时字幕和语音球联动。再二选一实测：TalkingHead 重做 3D 模型（本机能跑，脸会变），或用 SoulX-FlashHead 让照片开口（外观不变，需要 30 系以上显卡或云 GPU）。

    中到大人物方向

  6. 定升级办法

    列出 workspace-hook 的 12 处替换，能提成上游扩展点的提 PR。用自己的启动代码替掉对上游测试脚手架的依赖。每次升级按一份固定清单核对。

    中长期
