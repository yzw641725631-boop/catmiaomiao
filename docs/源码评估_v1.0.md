# OpenMausBot 源码评估 v1.0

版本：v1.0。日期：2026-10-21。范围：`openmaus-assistant`。结论依据分为源码事实、隔离实测与待验证项目。

## 结论

适合作为主助理和小助理的底座。新产品应复用其持久 bot、独立 thread、Chief 协调、审批和记忆，在同源客户端上实现沉浸式人物界面。完整代码 diff、Windows 语音入口和照片人物驱动需要额外实现。

## 能力与缺口

| 需求 | 已存在的事实 / 证据 | 首版处理 |
|---|---|---|
| 主助理派出小助理 | `server/chief-level-delegation.e2e.test.ts:29` 使用 `coordinate_bots`；`shared/wire.ts:75` 的 `TaskOpenedBy` 描述工作来源；本轮实测两名小助理 | 复用 Chief 与实际工作 thread，不在 UI 编造派工 |
| 工作时继续聊天 | 同一持久 bot 支持多个 task/thread；本轮一条 Chief 工作 thread 和一条陪伴聊天 thread 同时存在 | UI 把两个 thread 汇总成同一人物的时间线，保留各自来源 |
| 流式文字和状态 | `shared/runtime-events.ts` 的 `content.delta` / `request.opened` / `turn.completed`；`shared/wire.ts:937` 的 `ServerFrame` | 通过客户端投影映射为人物和任务状态 |
| 断线恢复 | `server/index.ts:16031` 的 SSE 入口支持 `Last-Event-ID` / `since`；`hello.resumed=false` 要重新取快照 | 复用 `src/lib/live-events.ts`，不可只累加 delta |
| 记忆与偏好 | `docs/memory.md`，`server/memory-capture.ts:28` 有候选置信度，`server/memory-upkeep.ts` 实现捕获/整理 | 复用原生记忆；用户显式偏好与推测的习惯分别呈现 |
| 记忆修订 | `server/routes/bot-memory.ts:103` 支持文件读取、`expectedHash` 写入和 journal/revert | 设置抽屉提供可见、可改、可撤回的入口 |
| 工作摘要 | `shared/digest.ts:20` 的 `TurnDigest` 含工具统计、文件分类、hookCoverage | 摘要描述观察到的工作；不等于测试通过 |
| 完整代码修改 | `server/checkpoints.ts` 有独立 shadow git 和前后快照；现有 digest 只有文件清单 | 新增受控 diff 契约；不可把摘要渲染成凭空生成的增删行数 |
| 任务停止 | `server/routes/bot-messages.ts:601` 接收明确的 `threadId` | 停止按钮始终绑定所选 thread；测试已确认不会停止另一个 thread |
| 播报停止 | `src/lib/tts/index.ts:61` 的 `Speaker.stop()` 中止请求、暂停声音并清理播放 | 与后台任务停止分开；真实音频播放尚未实测 |
| Windows 听写 | `electron/capabilities.cjs` 仅 darwin 原生听写；本轮能力函数验证 Windows 为不可用 | 必须增加独立语音输入适配，不宣称安装后自带 |
| Windows 桌面操作 | v0.1.121 的 `electron/capabilities.test.mjs:85`、`scripts/prepare-cua-win.mjs` 已有 Windows CUA 接线 | 当前源码比旧说明更完整；需要驱动就绪和实机验收，本轮未控制桌面 |
| 真人形象 | 上游 mascot/头像不是已批准照片人物的驱动资产 | 独立 AvatarDriver，不改 agent 推理循环 |

## 客户端接口清单

| 操作 | 当前接口 | 注意事项 |
|---|---|---|
| 启动探测 | `GET /api/health`、`GET /api/edition` | 本轮 edition 为 oss |
| bot 和任务快照 | `GET /api/bots` | 保留 threadId、openedBy 和 busy 等服务端状态 |
| 新任务 | `POST /api/bots/:id/tasks` | 审批级别显式 Ask；projectId 不代表文件目录 |
| 历史 | `GET /api/threads/:id/messages?before=...&limit=...` | 支持分页；响应含 activeLeafId；分支切换不能串历史 |
| 发送 | `POST /api/bots/:id/messages` | 明确 threadId 和稳定 sendId；有 queued/steered 等不同回执 |
| 审批/回答 | `POST /api/bots/:id/respond` | 绑定 threadId、requestId；不能从模型正文猜批准范围 |
| 指定停止 | `POST /api/bots/:id/interrupt` | 请求体明确 threadId |
| 增量流 | `GET /api/events?screens=off` | `message`、`message.patch`、`bot`、`runtime` 等；前台默认不拉屏幕图 |
| 调试事件 | `GET /api/threads/:id/events` | 调试日志；普通用户时间线不直接输出原始事件 |
| 记忆文件 | `GET/PUT /api/bots/:id/memory/file` | 写入携带 expectedHash；409 时保留用户编辑草稿 |
| 记忆日志 | `GET /api/bots/:id/memory/journal` | 支持对应记录 revert |
| 语音文本准备 | `POST /api/tts/prepare` | 本轮无语音配置时 ready=false |
| 合成 | `POST /api/tts/speak` | 每段最多 500 字符；密钥留在服务端 |
| 可选 Live | `POST /api/live/session` | 该实现依赖其特定语音提供方与密钥，本轮无密钥返回 409；未验证真实通话 |

这些是上游客户端协议，不能假设长期版本兼容。升级先固定提交、跑契约验证，再更新适配器。

## 实测记录

执行 `evidence/verify-upstream.mjs`，使用上游 `launchVerificationServer` 和 `runControlOmb`，真实本地 harness + 仓库假 Claude。共 10 项检查通过，204 个 SSE 帧。

1. 隔离服务器启动，确认 OSS edition。
2. 冷连接返回 `hello.resumed=false`。
3. Chief 为两名小助理创建真实工作 thread，两者同时等待受控 gate。
4. gate 未释放时，同一 Chief 的另一条 thread 完成陪伴对话。
5. 两名小助理结果返回，Chief 完成汇总，Ask 未被提升。
6. 缓冲区内游标恢复成功；其他服务器运行期游标要求重新同步。
7. 记忆可保存、journal 可查，过期 hash 写入返回 409，原内容保留。
8. 停止一条指定 thread，同一 bot 的另一条仍 busy 并最终完成。
9. 无语音配置如实报告未就绪；Windows 原生听写不可用。
10. 观察到真实 harness 的文字 delta、持久消息和工作 digest。
