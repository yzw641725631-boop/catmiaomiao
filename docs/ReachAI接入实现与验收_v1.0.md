## 范围与结构

用户在核对 ReachAI 的 LLM 与语音方案后回复“就按你说的来”，本轮据此实现。OpenMausBot 继续负责持久身份、记忆、独立陪伴/工作 thread、coordinate_bots 原生委派、工具和审批；ReachAI（产品名 Saturn Cloud）只提供模型与语音。没有修改 ReachAI 项目或线上配置，也没有复用其他项目凭证。

浏览器只访问同源本地入口 `http://127.0.0.1:5217`。模型经随机端口、随机凭证的私有兼容桥进入 ReachAI 原生接口；平台 Key 留在本项目配置中，内核配置仅持有私有桥的临时凭证。服务校验 Host、Origin、HttpOnly/SameSite Cookie，代理保持明确路由范围。

## 接口与限制

- 实例目录：`GET /model/instances`，只返回界面需要的模型标识和状态，去除连接凭证；保存时再校验实例类型与 ACTIVE 状态。
- LLM：`POST /model/chat/stream/events` 映射为内核兼容驱动的流，保留工具调用 ID、参数片段、reasoning、usage 和完成原因。工具结果可继续多轮回传；中断或 error 不能伪装为正常完成。
- 仅支持当前 ReachAI 文本内容契约。图片消息明确拒绝，不静默丢图或宣称已支持视觉工具。
- 整段 ASR：录音文件转为 `audioBase64` JSON 请求 `/model/audio/transcriptions`，不向 ReachAI 发送通用 multipart。
- 实时 ASR：AudioWorklet 将 48k/44.1k 音频转为 16k 单声道 s16 little-endian PCM，经本地受保护 WebSocket 转发 `/model/audio/transcriptions/stream`。当前 ReachAI 服务源码使用固定实时引擎，不按所选 ASR 实例切换，界面明确说明这一点。
- partial 只更新字幕，final 按 segment 去重累积；VAD 触发结束后仍等待 `reason:end`，再发送一次最终转写。取消和无语音不发送；发送失败则保留识别文字供重试，不覆盖已有草稿。
- TTS：`POST /model/audio/speech`，请求 MP3 和 `stream:true`；检查 HTTP 200 内的 JSON 业务错误，并兼容有效 base64 音频回退。支持浏览器 MSE MP3 时首段缓冲即可播放，否则完整下载后播放。
- 语音交互当前开启一次后持续轮流倾听/回复，两秒停顿自动发送，“转为打字”关麦；尚未实现全双工自然插话。
- Key 不返回给前台、不放进 URL，不记录在证据或截图。`runtime/companion-settings.json` 是含凭证的本地文件，当前没有系统保险库集成；内核模型调用仍会把必要对话和工具结果发送到用户选择的平台。

## 历史：初次接入时修复的关键问题

1. 创建 bot 的 soul、chiefOfStaff、approvalMode 原来放在请求顶层，实际接口会忽略。现改为 `settings`，主助理具备原生调度身份；只补齐已保存 bot 的缺失角色/空身份文本，不覆盖用户自定义身份。
2. 内核 `/api/config` 不提供完整 instances 读写，原来的模型热更新并未可靠更换驱动。现于空闲时重启本项目拥有的内核，复用同一数据与 bot/thread ID；启动失败恢复旧配置和连接。只改声音时不重启 LLM。
3. 对实时帧格式错误、迟到的麦克风权限、取消后的 WebSocket 握手/结果、结束时多个 VAD 分句分别回收资源并去重。无效 null/数组控制帧不会导致服务崩溃。
4. 播报的准备阶段也绑定取消，旧音频不能在停止后复活。私有桥及音频转发的关闭清理、大小/时间限制和错误信息均受控。
5. 发送后输入框聚焦曾滚动整个场景，让顶栏上移 36px；改用场景裁剪，1920×1080 复核顶栏位置及场景 scrollTop 正常。
