# 本地首版实现与验证 v1.0

> 历史阶段记录。2026-10-22 更新：后续 ReachAI 适配已实现并通过共 24 项隔离测试；当前入口为 [ReachAI 接入实现与验收](ReachAI接入实现与验收_v1.0.md)。下文保留初始 12 项测试阶段的事实。

版本：v1.0。日期：2026-10-21。项目：openmaus-assistant。状态：本地实现，继续验收。

## 当前实现

`app/` 已创建 React + TypeScript 前台：暖色书房、居中人物、右上对话/工作记录、左下两位小助理、底部输入和字幕、纯净视图、全屏按钮、模型/声音/记忆/偏好设置。背景和透明人物是图像模型基于批准图生成的独立资产，生成记录在 `design/asset-prompts-v1.json`。人物目前是静态图，没有口型或真实动作。

`adapters/` 启动固定版本的 OpenMausBot，提供同源本地入口 `http://127.0.0.1:5217`。演示用上游脚本模型、临时数据与独立 HOME；真实兼容模型配置使用本项目 runtime 数据，记忆与历史可跨重启恢复。上游 tracked 源码未改。

聊天与工作使用同一主助理的独立 thread，工作由原生 coordinate_bots 委派。发送有稳定标识并保护并发重复提交；请求被服务端接受后即使前台刷新失败也不会提示重新发送。此保护不等同于跨进程崩溃的全事务 exactly-once。

工作明细只对本项目创建的工作目录做有界文本快照，跳过密钥、隐藏文件、二进制和超大文件。隔离演示的文档确实写到本机，校验由真实 Node 命令执行；正式工作若没有捕获测试结果，不标记为测试通过。

记忆支持 hash 冲突保护、手动修订、修改历史与可撤销项。语音包含录音入口、通用 multipart ASR 服务设置、上游 TTS 配置与播放中断控制；真实麦克风、声音与人物推理仍未验收。

## 验证结果

2026-10-21：Node v24.19.0 执行 `--experimental-strip-types --test tests/*.test.mjs`，12 项通过、0 失败、0 跳过，约 13.55 秒。覆盖：

- 本地服务的 Cookie / Origin 与代理范围限制。
- 并发重复提交只创建一条工作；两名原生小助理实际协作写文档，期间可继续聊天；真实文件可下载。
- 停止指定工作不影响独立聊天。
- 记忆过期 hash 返回 409；journal 撤销恢复原文。
- 使用本地模拟兼容厂商的真实 OpenMausBot 驱动，验证 LLM 流、Key 不回显、ASR multipart 与重启后历史/记忆保持。
- 稳定 message ID 合并、迟到流事件、独立错误、Windows 文件链接与安全 URL。
- 播报准备期间取消；播放时打断会暂停音频、释放 URL 并跳过后续片段（模拟 Audio，无真实扬声器验收）。

TypeScript 检查、Vite 生产构建通过。最终 JS 约 363.24 KB（gzip 114.79 KB），CSS 26.70 KB（gzip 6.80 KB）。无重新运行全量上游测试；上游未改，先前隔离底座验证 10 项单独保留。

浏览器已看到两名小助理完成、真实 report.md 新增差异与命令退出码 0；已生成文件可通过消息授权接口下载。新版记忆历史 UI、1920×1080 / 1366×768 / 125% 布局、纯净视图键盘和真实语音仍待完整回归，不能把构建通过当作这些体验已验收。

## 已修复的问题

- 小助理实际 cwd 位于 `DATA_DIR/task-workspaces/...`，不是 memory workspace；修正相对路径后报告落盘、下载与校验通过。
- 上游 Electron 私有 parentPort 在 Node 子进程下缺失；用 IPC 适配传递私有请求能力，保留原有认证，不修改上游为匿名可写。
- Markdown 默认 URL 处理丢失 Windows 文件引用；受限 URL 转换保留文件路径，下载仍走 message-scoped 授权接口。
- 工作卡摘要去掉 Markdown 路径，避免临时绝对路径挤占界面。

## 模型方向的新输入

用户要求优先查看 ReachAI 的 LLM 与语音。只读核对已完成，具体结论见 [ReachAI 接入核对](ReachAI模型与语音接入核对_v1.0.md)。建议复用其模型层，不用它的 Agent 执行层替换 OpenMausBot。当前仍是通用兼容服务设置；ReachAI 原生 JSON/SSE/音频协议的转换尚未实现，真实在线实例尚未授权核验。

## 启动与退出

运行 `scripts/start.ps1 -Fixture` 可启动独立演示；不带 `-Fixture` 时读取本项目自己的服务配置，未配置时仍用隔离演示。需要 Node>=24 和已有项目依赖。前台和服务仅监听本机。

控制台输入 `quit` 再回车可正常退出，关闭拥有的子进程，并在 fixture 清理前复制数据到工作区 `归档/openmaus-assistant/`。早期用 exec Ctrl+C 强制中断的一份临时 fixture 目录尚保留于系统 Temp，未执行删除；不要直接批量清理。
