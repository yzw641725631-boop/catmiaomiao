# Windows 文件工具接入与验收 v1.0

版本：v1.0。日期：2026-10-22。项目：openmaus-assistant。状态：受限真实文件链路通过；汇总准确性仍有已知问题，G5 未终签。

## 实际能力与范围

用户要求“继续接通”，本轮接通此前缺失的 Windows 文件工具。当前提供 `list_files`、`read_file`、`write_file`、`check_file`：在每项工作新建的独立目录内读写 UTF-8 文本，支持 Markdown、JSON、JS/TS、Python 等常见文本扩展名。覆盖必须提供读取时的 SHA-256，并在替换前将旧字节归档。未提供删除、任意终端、安装、电脑控制、数据库或外发工具；网络检索也未在当前工具清单中开放。

校验只支持 UTF-8、JSON 解析和固定 `node --check`（JS/MJS，仅语法检查，不执行模型代码）。它们不等同于运行项目测试。真实验收本轮只创建并校验 Markdown；覆盖冲突、归档、JS 语法检查等由隔离测试验证。

## 绑定与安全约束

- OpenMausBot 固定源码未改。`workspace-hook.mjs` 使用 Node 24 模块加载钩子，在已知入口的指定位置注入启动适配；校验源码完整 SHA-256 和唯一锚点，版本变化时拒绝启动并要求复核。
- 每个原生 turn 通过私有 IPC 向本地运行时申请目录。运行时根据自己的工作登记、三个已选机器人及原生 task.openedBy 祖先链决定范围；模型参数不能决定根目录。陪伴 thread 和外部机器人得不到文件工具。
- MCP 进程拿到当次已验证根目录，工具参数只接受相对路径；拒绝越界、绝对路径、ADS、隐藏/凭证文件名、Windows 保留名称、符号链接/目录联接、硬链接、二进制和超过 64 KB 的单个文件。
- 同一工作的 MCP 进程共用位于工具范围外的文件锁，写入/校验互斥；检查并发修改时不静默覆盖。正常释放的锁移动到归档。进程在持锁期间被强制终止可能留锁，不能按超时擅自抢占；需本地操作员核对后归档残留锁。
- 原生权限卡逐次授权，不设置全程自动允许。前台按真实 bot/thread 路由小助理授权，工作页和纯净视图均能提示待处理事项。卡片显示操作、文件名和即将保存的正文。
- 已暴露的内核工具收紧为聊天/记忆/原生派工/当前文件工具，保留原始 schema 校验，不强转非法数组或绕过权限。

## 工作状态与恢复

工作登记、初始文本快照、原生身份和 thread ID 持久化。实际文件差异取初始/完成快照；真实写入与校验回执在工具范围外保存，测试列表只认已记录的退出码和文件哈希。文件后来发生变化时，旧校验不再显示为当前有效。

失败任务可以在原 thread、原目录重试，保留失败记录，并复用发送标识防止重复提交。原生小助理返回 `NEEDS INPUT` 时，页面展示补充说明入口；服务从原生 question message 的 threadRef 定位回答对象，并核对同一工作的祖先范围，不接受任意目标机器人。问题已收到回答后拒绝重复回答。
