## 原始研究基线（动态团队已由后续实现更新）

先补齐 OpenMausBot 已有能力的接入，再接标准 MCP 工具和成熟交互组件。现有产品把底座缩减成固定三人、文本任务和若干能力抽屉；目前的测试通过只覆盖已实现范围，不能代表产品达到 Grok Bot / Muse 的完整程度。

本轮按此前明确提到的 Grok Bot 与 Meta Muse 核对。用户已澄清“Chávez”是创建小助理，已优先接通；Skills 是另一项研究候选。Vault 名称仍未确认，不据此认定为 Obsidian 或路由到其他项目。

源码核对基于现有固定提交 `97a4a1cab96ab3d07b0c7dac275f69afc6e7a8dc`。公网仓库状态另作带日期的快照；未更新本地上游。

## 产品参考带来的要求

[Grok Bot 官方指南](https://x.ai/bot/guides/grok-bot-101)提供电脑、可接管的浏览器工作、专门岗位、多人协作和例行任务等产品入口。这里应复用的是“交给谁、在哪里做、何时需要我、结果在哪里”的连续流程。官方能力描述不等于本机接入验收。

[Muse 官方设计说明](https://introducing.muse.ai/)把长期主对话、独立话题、目标、活动记录、结构化确认和可交互成果连接起来；[发布说明](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)也说明其独立电脑和后台执行方式。对本产品的设计判断是：右侧只放一条不断变长的文本记录，无法承载这种工作方式。应该补内容对象和连续操作，而不是继续增加相同的大卡片。

设计审计与待实现模式另见 [交互研究决策](../ui-system/product-research-decision-20261023.md)。本轮查阅公开官方材料，没有登录或操作这些产品的私人账户。

## 接入时必须一起完成的链路

动态团队：从原生持久 bot 与团队关系发现成员，校验创建结果属于当前 Chief/section，维护本地权限范围和任务祖先。新成员首先具备明确的模型和工具选择，再允许委派。前台根据真实 bot/task 事件出现新成员；刷新和重启后仍存在。不能只在左下画出第三个图标，也不能仅放开 `create_bot` 却继续拒绝新成员的 MCP 请求。

技能：展示名称、用途、来源、内容、启用状态和候选版本。对话提出可复用步骤后，使用原生 `skill_manage` 提交；待审核时保持当前版本。导入使用原生 GitHub 解析和审阅流程。技能只是指导，实际读取、写入、浏览和电脑工具必须已经接通。

电脑：当前 Node harness 没有原生 CUA 宿主，须恢复 Electron main 生命周期、固定驱动、真实可用性检查、屏幕帧和控制租约，再接 ComputerPanel / LiveDesktop 的接口。电脑状态至少区分未配置、启动中、正在操作、等用户接管、暂停和失败。Codex 自身的开发工具不是终端产品可继承的电脑服务。

浏览器：原生桌面 Browser 和外部 Playwright 属不同运行位置，UI 要显示当前使用哪一个，工具目录只挂所选方案。用独立 profile 开始，不擅自接管用户的浏览器资料。第三方网页内容作为任务资料；账户登录与最终动作由应用中对应流程处理。

成果：事件保留 botId、threadId、messageId、toolCallId 和实际文件/资源位置。摘要气泡只解释发生了什么，正文进入阅读器、表格、网页预览或 diff。MCP Apps 的 UI 发回工具操作时，仍经原生执行与审批流程；模型生成的“完成”文字不能产生假文件或假按钮。

## 推进顺序与验收

1. **先补原生创建小助理、Skills、MCP 管理。** 在隔离 harness 创建新成员、刷新发现、委派、回收结果；技能候选经确认启用后被下一次任务使用，版本冲突保持旧版。验收看真实持久记录，不只测工具名称出现。
2. **接真实浏览器与 Computer Use。** Playwright 先用本地合成网页验证导航、填写、返回结果；Windows 固定驱动只在专用测试窗口验证观察、输入、接管与停止，再做桌面产品入口。当前阶段不能宣称已完成。
3. **根据实际事件重组对话、任务和成果。** 优先完成浏览器操作、生成文档、代码修改三个真实过程；支持从结果继续提问、从需要接手的位置返回，以及会话中继续安排另一项工作。
4. **补长期目标、例行工作与连接器。** 先选择一个用户实际使用的应用走通授权、调用和回执。现有提醒与原生 routines 做明确映射；迁移前保留数据、运行次数和恢复记录，不运行重复的调度器。

每一阶段复用现有上游和隔离验证，再补接入契约。原研究时的 79 项检查已在动态团队实现后扩展为 83 项，另有真实模型/页面/重启证据；未将这些结果扩张为尚未完成候选的验收。

## 未决项

- 创建小助理已确认并实现；Vault 名称仍未确认，不据此安装未知仓库。
- 当前模型在结构化网页 / UIA 下的完成质量和图像输入仍需 POC，不能只凭“兼容 API”判断支持截图。
- 公网 OpenMausBot 已有新提交，本地维持固定版本；需要的能力在固定版本中已存在，暂不升级。
- UI 扩展是 draft，下一轮应基于真实内容审查可操作原型；不能用另一张生成效果图充当交互验收。
