# 助理改名与请求耗时验收 v1.0

日期：2026-10-25，Asia/Shanghai。沿既有 G2/G4 本地开发范围，独立 G5 未终签，G7 未申请。

## 改名

用户在主对话要求正式改名为“小蕊”，模型回复没有改名工具，并指向尚不存在的设置入口。原因是产品只有创建小助理的接口，没有改名工具或表单。

现在可以直接说“以后叫你小蕊”，主助理调用 `assistant_rename_assistant` 保存后确认。也可点对话顶部名字，打开“我的助理”，点名字旁的笔修改；主助理和小助理均可编辑。保存中禁止重复提交，失败保留输入，Escape 先取消改名，再关闭面板。对话标题、消息作者与流式回复使用真实名字。原名称保持在原始历史文本中。

实现复用原生 `PATCH /api/bots/:id/profile`，只发送 name；不新建身份，不更改 soul、模型、工具权限或任务。`POST /companion/team/rename` 沿同源 Cookie/Origin 认证，只接收 botId/name，限制当前团队、单行 1–80 字，拒绝同组重名。创建和改名共用串行队列，避免并发抢占名字。工具只允许主助理从主对话按用户要求调用，默认改自己；本项目受信任的常规工具授权允许直接执行，外部同名工具不能借此免审批。

实际 5217 页面已保存“小蕊”；619×892 视口无横向溢出，取消编辑后保留面板，关闭后对话标题同步。见 [保存界面](../evidence/name-latency-20261025/name-saved.png)。

真实当前 DeepSeek 在独立运行目录中调用工具保存“小蕊”，完成文字确认，没有额外审批；两次模型调用分别 7.899 秒、4.185 秒，包含启动和轮询的总时长 15.788 秒。[真实模型回执](../evidence/name-latency-20261025/live-name-2026-10-25T13-46-44-674Z.json)。日常会话未被写入测试消息。

## 耗时结论

用户最近两次实际问候/改名请求从原始用户消息到最终回复约 12.248 / 12.920 秒；模型桥日志记录 11.196 / 12.032 秒，均一次成功、没有工具调用或重试。因旧日志没有首字计时，不能把这两个完成耗时直接叫作首字延迟。

本轮在相同所选实例做独立合成探测：网关响应头/第一段输出在 11.959 秒返回，可见文字在 12.584 秒出现，12.586 秒完成。主要等待发生在本地请求发出至网关开始返回之间；仅凭客户端无法区分网络、平台排队、提供商排队、推理或网关缓冲各自占比。

电脑被分配给主助理时，简单问候也带完整工具目录。本轮新增改名后实际目录 84 项，工具 JSON 共 126,776 字节；合成问候请求约 154.6KB，其中所有工具定义约占 82%，主要大项是电脑操作工具。用户之前 83 项请求约 181–184KB。较大的输入可能增加处理成本，但没有控制变量证据证明它独自导致 12 秒等待。

已做两项改动：

- 发给模型时移除历史中本适配器追加、已经过时的能力/工作状态说明，仅保留最新说明。用户文字、工作目录、工具调用/回执和推理连续性字段保持，原生消息数据库不修改。两轮原生合成问候中省去约 4KB；[目录及字节核对](../evidence/name-latency-20261025/2026-10-25T13-43-07-961Z/report.json)。没有裁掉工具或悄悄改变电脑授权。
- 诊断日志新增 headersMs、firstOutputMs、firstContentMs、messageBytes、toolBytes、historyNotesCompacted、historyBytesSaved。首段输出包括推理/工具调用，firstContentMs 才是可见正文，未出现时为 null。只记录计时、数量和字节数，不保存提示词、回复或密钥。

另一次独立探测上游返回 401。早期比较脚本没有重建被投影省略的旧说明，两组实际请求相同，已在[原始回执](../evidence/name-latency-20261025/2026-10-25T13-40-33-341Z/report.json)明确标记不能作优化前后比较；随后修正脚本并仅核对目录/字节，不反复请求云端。不能用一次成功宣称模型服务长期稳定，不能把一次上游 401 直接判定为本地平台密钥失效，也不能宣称本轮已稳定提速。未改变当前模型、平台凭证或云端配置。

## 磁盘与数据保持

验证中发现 J 盘剩余 0 字节，原生创建测试明确返回 ENOSPC；这会威胁新消息/配置保存，但不是前述远端等待的已证实原因。原计划跨盘迁移归档的复制校验/删除命令被自动审批审查拦截，工具只返回 blocked by policy，未执行迁移或删除。改用 NTFS 原地无损压缩本项目旧构建归档及 evidence，保留原路径和文件内容，恢复约 1.3GB 空间；达到可继续验证的空间后停止压缩。没有清理其他项目或用户聊天。

本地服务先确认团队空闲，再正常停止、归档数据库与配置、重启加载接口。前后核对 [before.json](../evidence/name-latency-20261025/before.json) / [after.json](../evidence/name-latency-20261025/after.json)：全部 417 条原生消息的内容哈希一致，记忆索引一致；主助理 ID、主对话 ID、三位小助理、全部任务 ID、模型设置、本领配置和 main.md 哈希保持。唯一预期的资料变化是主助理名字。
