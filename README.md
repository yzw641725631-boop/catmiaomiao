## 创建小助理

在对话中说“帮我创建一位行程助理，负责规划行程”，或点左下“添加”填写名字、职责和工作方式。“我的小助理”列出完整团队，选择“安排工作”后补充目标发送。新成员可接任务、回报结果，重启后仍在；常驻仅显示最近两名。

## 新能力的使用入口

- **技能与工具 → 技能**：选择助理，导入或在对话中提出做法。新提议先审阅完整内容，确认后启用；相关任务实际读取技能，不只显示一个标签。
- **分配本领**：为指定助理选择专用浏览器、已连接工具或本机电脑。电脑先准备固定驱动；原来未授权的助理不自动获得整台电脑。
- **工作 → 交付文件**：直接阅读文档/表格、下载真实 DOCX/XLSX；实际有浏览器/电脑活动时，可打开相应工作现场并接管/交还。
- **目标**：建立持续事项，查看每位助理的回复和实际文件，暂停或补充后继续同一目标。原生协作每轮有 13 次上限，不承诺无限自动执行。
- **例行工作**：创建单次/每日原生工作，查看运行历史、暂停、现在执行或停止。关闭本地服务后不继续运行。
- **邮箱与日历**：QQ/163/企业 IMAP 填邮箱与授权码；Google、Microsoft 365/Outlook 填各自 OAuth 客户端并在本地完成登录。保存后测试，再分配给助理。真实账户尚未登录，不能把工具测试成功当成已收取私人邮件。

当前模型已实际完成“技能 → 网页填写/点击 → Word/Excel”，持续目标的原生三轮协作和重启恢复在隔离模型通过。当前模型目标复验遇到 Saturn 上游 HTTP 503 网页验证；若失败发生在任何模型输出之前，传输层会自动重发最多两次，失败证据仍保留，已有工具调用不会重放。通用 MCP Apps Host 和真实账户事件触发尚未完成，人物仍为批准的静态分层图。

## 本地运行

```powershell
& 'J:\agent_project\projects\openmaus-assistant\scripts\start.ps1'
```

随后打开 `http://127.0.0.1:5217/`。已有服务占用 5217 时直接使用该页面，不重复启动。输入 `quit` 回车可以正常退出服务并归档演示数据。不要通过按进程名批量结束其他项目。

需要脱离当前终端运行时，使用 `scripts/start-background.ps1`；正常结束用 `scripts/stop-background.ps1`。监督进程通过 stdin quit 关闭内核，身份、聊天与文件保留；这不是 Windows 服务或开机启动安装。本轮已用该方式保持本地服务。

不带 `-Fixture` 时读取本项目 `runtime/` 中的配置，没有配置则使用隔离演示；保存真实连接后，下次启动沿用该连接。显式添加 `-Fixture` 会强制进入演示。真实会话的身份、聊天、工作记录和记忆独立持久化，演示数据不混入其中。

安排工作时，每次任务会生成自己的产物目录。文件操作在右侧逐次确认；小助理需要补充资料时可直接在问题卡回答。失败的任务可在工作页点击“重试此任务”，不会另建任务掩盖失败。点击“工作明细”核对真实差异和校验记录。

工作详情默认显示“助理回复”：文档助理是谁、实际完成的步骤和交付文件直接可见。点击 report.md 一类文件行阅读排版正文，下载走原生消息中的精确路径；需要检查工具参数/审批再切“执行过程”或查看文件差异。超时问题不再一直显示待处理，历史失败保留。普通用户消息不显示本地附加的能力提示。

### 连接 Saturn Cloud（ReachAI）

本机已配置真实 LLM，直接聊天即可。以下步骤用于更换实例或重新配置；现有模型厂商 Key 留在 ReachAI，助理只保存专用平台调用凭证。

1. 打开“设置 → 模型连接”，连接方式选“Saturn Cloud · 统一模型与语音”。
2. 平台地址默认 `https://saturn.starhubs.online`，填写有 `model:read`、`model:invoke` 权限的平台 API Key。
3. 点击“读取可用模型”，选择 ACTIVE 的 LLM、录音转写 ASR 和助理声音 TTS；ASR/TTS 可暂不启用。
4. 音色留空采用实例默认音色，调整语速后点击“保存并使用 Saturn Cloud”。保存后页面显示“Saturn 已配置”；这表示配置已保存，不表示声音与模型效果已经验收。
5. “声音”页可试听已保存配置，选择录音结束后识别或实时识别。实时识别走平台统一引擎，所选 ASR 实例只用于整段录音。

点击一次“开启语音对话”，说完停顿 2 秒自动发送，回复播完继续倾听，无需每轮点击；“转为打字”关闭麦克风并保留文字草稿。首次开启仍遵循浏览器权限。设置中的“麦克风”可选择耳机输入、观察音量或做本地测试；本地测试不上传声音。思考和播报时暂停采集，当前不是全双工。语音的对应成功回复自动播报，朗读开关另控制打字回复；静音不发空消息。MSE 支持 MP3 时边下边播，否则回退完整音频播放；自动播放被浏览器限制时可点“听一听”。

当前每次只由一个页面持有语音会话；另一页显式开启后旧页暂停，避免双重采集。超过 45 秒仍无对应终态回复时恢复倾听，不自动重发原句；也可点麦克风“继续说话”主动结束等待。稍后结果保留在记录。QA 页面完成测试后关闭录音，不与用户页面同时持续采集。

Key 仅保存在本项目服务端配置 `runtime/companion-settings.json`，不回传到前台、不放入浏览器存储或 WebSocket URL。该本地配置文件包含凭证，应由用户管理；当前没有接入系统凭据保险库。不要把 Key 发到聊天、提交源码或填到通用兼容 API 的 URL。其他兼容服务仍可在连接方式中选择。

需要 Node >=24、pnpm 10.33.0；使用现成 Codex Node 不修改系统默认版本。依赖已经在项目内安装。需要重建时，在 `app/` 执行 `node node_modules/typescript/bin/tsc --noEmit` 和 `node node_modules/vite/bin/vite.js build`，这里的 node 必须指向 Node 24。本机完整路径见下方验证命令。不要在项目根目录创建散落应用代码。
