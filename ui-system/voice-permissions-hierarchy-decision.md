# 人声、按助理授权与对话层次修订

日期：2026-10-24。状态：已实现并完成本机开发者检查，独立 G5/用户验收待签；沿用户明确提出的本地修订。适用：个人高频 Windows 桌面 Web 应用，不是营销站。事实来源：已批准书房/人物、现有 App.tsx/WorkDetail/ConversationFeed，以及用户本轮 Bot 截图。没有额外 PRD；需求以本轮对话和开发准入记录为准。

## 复用与扩展

- 复用 C01 场景与人物、既有原生 Agent/线程/成果/审批，不更换用户认可的形象。
- 扩展 C02 为主对话层。用户消息是紧凑气泡，助理回复是可阅读气泡；每段表达、时间和作者有稳定归属。一般成功过程不占用主对话高度，收进活动入口；失败使用短状态入口，点开才是原始过程。
- 扩展 C03/P02 为工作动态层。工作列表以紧凑活动行呈现标题、实际状态/作者和时间；点击整行进入第二层详情。详情先给结果和文件，再按需查看执行过程、差异和审批原文。不得只换圆角而保留所有步骤同级堆叠。
- 扩展 C06 为待办行动条。只显示一个可理解的动作与对象，真正待确认仍可达；外部工具的内容和技术参数在展开区。旧请求不自动追认。
- 扩展 C10“分配本领”：每位助理、每种工作位置分别保存“每次询问/完全允许”，未允许的资源没有使用权；外部 MCP 和技能许可不随电脑模式扩张。原有设置默认仍询问。选择完全允许时，就地说明适用电脑/浏览器和后续任务，支持改回。
- 扩展 C04：音量表只表示收到声音；开始一句话/等待两秒停止由实际人声检测决定，不由低音量阈值或识别幻觉文字决定。模型在本地加载，测试不上传噪声样本。

## 层级与交互规则

一级主对话：内容优先，顶部连接/当前状态，底部持续输入。对话里后台工作只显示紧凑关联入口，不能整页重复展示已处理审批。二级工作详情：返回原列表/原阅读位置，结果与文件优先。三级过程/原文：明确展开/收起与所属任务，不弹无归属全局卡片。

loading 保留已有内容；失败是所属请求的短状态，展开查看具体原因；断线保留草稿；禁用控件说明原因；权限保存显示实际回执，忙碌冲突不假成功。keyboard/IME/Escape/焦点恢复与 reduced-motion 沿既有规则。窄窗口在同一区域切换列表/详情；不把桌面双栏直接压成三层小卡。

## Token 与范围

保留书房 primitive、纸色 surface、ink、hairline。消息填充、圆角、间距、活动 icon background 经 semantic → component 映射；只影响对话、工作动态、过程/行动条和分配本领，不改变人物。避免无功能胶囊、所有元素套同一种框、每行一个大卡片、中文按钮散落在内容周围。

最终检查必须包含：短/长回复、后台工作、失败与待审批并存、按助理授权后重启/撤销、噪声误触发与轻声人声、窄窗口和上翻历史。静态截图不代替操作验证，合成音频不冒称真人听感。

## 实施与质量门核对

六类UI文档已同步，均注明这是个人高频Windows本地应用而非营销站；已批准人物/背景和用户Bot截图为事实源。局部token、组件职责、列表/详情页面、语音和授权交互分别记录。加载/空/错误/禁用/成功/冲突状态沿现有实现，模式保存失败回滚测试通过。480×900窄窗口使用同一阅读面，权限单列；实测无横向溢出，输入和面板分离，返回保留筛选/焦点。没有引入另一套设计系统。

## 后续扩展：状态与失败恢复

2026-10-25 增加系统状态抽屉，沿用“配置、连接、真实验收分开表达”的规则。连接标签进入状态中心，按本机服务、LLM、语音、视觉和后台调度分组；视觉通道即使已配置也显示“需要检查”，不把上游令牌和真实图片派工混为成功。模型发送失败保留原消息和幂等 sendId，入口提供重试；后台监督进程只对意外退出有限重启，避免把失败模型请求无限重放。状态中心是一级诊断入口，具体配置仍回到模型/声音设置，工作失败仍在所属工作详情中重试。
