# 原型与实现约束

2026-10-24 最新：按用户 Bot 截图落实三层交互，详见[降噪、权限与交互验收](../docs/降噪与权限交互验收_v1.0.md)和[本轮决策](voice-permissions-hierarchy-decision.md)。本段为当前规则，下方 10-23 及更早增量保留为历史；冲突处以本段为准。

必须实际操作对话、动态筛选、待确认、成果、过程、返回和文件阅读，不用同尺寸卡片重复包装。必须用人声模型测试噪声/轻声/取消，不以RMS模拟模型通过；模型/WASM本地同源，资源加载失败显示错误，不能退回噪声触发。完全允许只对保存的助理和设备生效，不默认开启；实际身份/历史不因UI重做改变。108项和本轮浏览器证据不能代替用户审美或真人长时间验收。

日期：2026-10-21。状态：review。适用：下一阶段 UI 原型和正式前端。

1. 使用批准图的人物、书房、暖白面板和布局；背景、人物、UI 必须分层。完整截图只能作参考，不能把截图上的按钮当可交互实现。
2. 采用 P01～P04 和 C01～C08。默认只有一个主场景，没有常驻传统左导航或密集仪表盘。
3. 先按1920×1080、1366×768、125%缩放检查，记录实际面部/手部保护区；不通过缩小所有文字解决挤压。
4. 需演示：空历史、文字回复中、两位小助理执行、等待审批、完成、失败、断线、语音拒绝、记忆409冲突、纯净视图、减少动效。
5. 原型演示数据显式标识“演示”。正式页面默认不生成虚构任务、测试通过、文件diff或假的百分比进度。
6. 稳定ID由 botId/threadId/messageId/turnId/requestId 组合，不用列表下标表示可操作对象；同一事件不能因重连变成两条。
7. `message.patch`更新原条目，runtime delta只更新对应流；历史回放不能重新触发语音。时间线保留来源与展开明细。
8. 录音、播报、模型生成和后台任务分别建状态，输入图标不能用一个“忙碌”布尔值替代全部行为。
9. 语音不可用保留文字；人物模型不可用保留同一人物清晰图；当前静态图必须明确不具备自动口型。
10. 前台不存模型/语音密钥，不新增宽松CORS，不绕过原生审批。代码内容、模型HTML和文件链接均走受控渲染。
11. 首版只做本地桌面，移动端另立规范；窄窗口降级为片层，不宣称已完成手机设计。
12. 交付时保留实际截图、关键操作结果和未验证项；文档自检不等于视觉QA。G2/G4前不把本规范标为已上线实现。
