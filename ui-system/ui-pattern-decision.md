# 本机能力与工作查看：UI 决策

## 2026-10-23：动态小助理（已实现子集）

用户澄清“创建小助理”。复用 C03 的状态行、C06 的实际动作回执及 P04 的抽屉；新建 TeamDrawer，不新增另一套主聊天。左下显示真实成员数、添加入口和最近两名；完整团队以名字、职责、实际忙碌状态和“安排工作”分隔行呈现。添加表单只要求名字和职责，工作方式选填；提交中禁用，错误保留在表单，成功后回到成员列表。

原生 create_bot 本地直接应用时，回执显示“已创建”和实际职责；pending/failed/expired 不能写成成功。创建不意味着任务已完成。安排工作预填自然语言名字，焦点进入输入；用户补充具体目标再发送。所有状态来自实际 native bot/card/task，不以模型自述或假进度替代。

抽屉进入暂停语音，关闭按现有规则恢复；任务持续运行。表单聚焦名字，提交/成功后聚焦 dialog，Tab 循环，Escape 恢复入口；安排工作时不把焦点抢回抽屉入口。桌面 1280×720 和窄窗口 390×844 已检查，窄窗口整宽、正文独立滚动、无横向溢出。83 项测试/类型检查/构建、真实模型创建与派工、手动创建及重启成员保持均有证据。详见 docs/动态小助理接入与验收_v1.0.md。

能力与交互研究中的重命名/归档、电脑、目标、Skills 和富成果仍是 draft，不能以本子集验收代替。

## 2026-10-23：对话阅读与文件交付修订（当前规则）

用户明确否定此前卡片外观和工作内容可读性，并反馈对话卡住。本轮按 product-ui-system 复用 P01/P02/P04，沿用已确认人物、书房和暖色调；重新组织 C02 记录表面，下面 10-22 的尺寸为历史阶段值。没有引入营销页或更换形象。

- 右侧为不透明纸色对话窗，桌面默认宽 440px、展开 610px，top=94px、height=100dvh−118px；>=1600px 对应 480/660px。不再把长对话压进 370px 高度卡片。用户消息右对齐浅绿气泡，助理正文左对齐，姓名/时间和朗读为次级信息。
- 记录窗打开时输入留在人物所在区域，与右窗并排；展开时相应让出阅读空间。窄窗口改成可收起片层，低高度优先保证字幕与输入；不能通过缩小整页达到适配。核心值在 conversation-ui.css，加载顺序为 style→assistant-services→conversation-ui。
- 工作列表使用细分隔行；详情默认“助理回复”，交付文件为清晰可点的文件行。文件标题取实际产物正文 H1，不用长参数串作为阅读标题；中文回执只来自实际成功步骤。小助理名字、原回复开头和“阅读完整回复”明确显示，主助理重复汇总折叠；“执行过程”保留真实日志。
- 点击文件显示独立排版阅读页，正文以 Markdown/GFM 渲染，技术差异保留在证据入口；下载严格使用原生消息中的实际文件链接。关闭按钮、Escape、焦点循环和恢复都要验证。
- 已超时的 needs-input 问题必须根据后续原生 failed 通知关闭，不继续显示待处理；已回复、已交付、未完成和等待状态分别有文字。失败历史不删除，用户可以查看。
- 语音由一个页面持有会话；显式在另一页开启会转交，旧页停止。当前请求的已证明终态回复可先播报，再继续听，不因旧派工 pending 永久等待；超过 45 秒只结束语音等待，不重发原消息。“继续说话”允许主动打断等待。

质量检查：TypeScript、79 项测试和构建通过；实际对话连续两次回复、工作文件阅读和下载已核对；1280/1366/1024 及窄视口检查记录在 conversation-repair-20261023。未将这些证据当成人声连续两轮、125% 物理缩放或原生 Windows 壳验收。

## 2026-10-22 初始扩展记录

日期：2026-10-22。适用：Windows 桌面个人助理，日常频繁使用。来源：已确认书房人物布局、当前 React 页面、用户对功能/显示问题的反馈及“都要做”的明确范围。设计方法：product-ui-system；不采用营销落地页重做。

复用 P01 陪伴、P02 工作查看、P04 设置抽屉，保留 primitive/semantic token。没有全局更换颜色和人物。

扩展 C02 记录面板：对话与工作分开，可展开；工作列表→过程→产物/校验，返回保留原任务。子助理状态可点击，支持从普通对话派工的任务。真实步骤默认显示中文摘要，技术详情折叠。

新增能力抽屉：复用 P04 布局，四个本地 tab 分别是文件夹、网页、记忆、提醒。目录读取范围、写入勾选、撤销、候选偏好确认和提醒动作各自明确；保存失败紧邻动作，空状态不放假内容。打开抽屉暂停语音，关闭恢复，后台任务不取消。

状态规则：成功模型轮显示“已回复”；实际保存+校验回执才是“已交付”。等待小助理与等待用户有不同状态。任何当前终态失败显示未完成。提醒“已发起工作”不能写为工作完成，触发后可进入工作页。

桌面和窄窗口：>=1100px 常驻右上记录；窄窗口/低高度默认收起记录，再按需打开，正文独立滚动；不整体缩小字号。细路径换行，复选框与文字同行。动作至少 36–44px。人物原图保持，不扩大浮层遮脸。展开工作是用户临时操作。

交互状态必须具备：读取中、未接入、无内容、提交中、保存成功、连接/校验失败、只读、等待审批、版本冲突、任务停止、原任务继续、提醒暂停/取消/触发。公开网页说明当前仅检索与正文，不用虚构浏览器/连接器按钮。

质量门检查：已有 UI 和明确需求已核对；语义/组件模式沿用；新增范围和状态已转化为实际组件；键盘焦点、Escape 和窄窗口截图实测后记录到交付审计；没有以泛化视觉建议代替产品规则。尚未实现原生 Windows 壳与 125% 物理屏幕验收。

实测：1280×720 展开面板底部 464px，字幕顶部约 525px，输入底部 691px；1366×768 面板底部 512px、字幕顶部约 573px；1024×768 面板底部 495px、字幕顶部 581px；1024×576 面板底部 356px、字幕顶部 409px。均无页面横向溢出，输入在 viewport 内。390px 能力抽屉填满宽度并独立滚动，文件路径折行；这不是原生移动端验收。抽屉焦点先进入 dialog，Shift+Tab 到末项、Tab 回关闭按钮，Escape 关闭；重载后已确认偏好仍可见。工作详情打开时 scrollTop=0，普通对话继续跟随。当前全量检查为 TypeScript、72 项测试和构建全部通过。
