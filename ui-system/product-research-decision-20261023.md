日期：2026-10-23。状态：动态团队、技能/应用列表、电脑/浏览器工作面、DOCX/XLSX 阅读器和目标/例行工作已实现，独立终验待签；下面研究草案保留初始判断。适用：个人频繁使用的 Windows 桌面与本地 Web。用户要求补 Computer Use、创建小助理和丰富交互，并否定此前界面的模板感；实现不等于用户已认可效果。

## 当前接入决策（2026-10-23）

本轮用户明确否定当前卡片质感。P01/C02/C04 修订为持续可交流的主对话：已接受的后台工作不占用麦克风等待，思考期间可再说一句；打开工作现场只切阅读，不停止语音，密钥/声音配置才暂停。消息按作者与时间分段，常规工具集中为可展开的过程行，已处理审批不再作为大卡片铺满。待确认动作是简洁行动条，结果为文档/表格入口与实际回复。保留批准书房、人物和暖色体系；只调整对话/工作表面、字重、边框、圆角与留白，不更换资产。附件为输入上方缩略图，可删除草稿、粘贴和拖入；发送前提示图片由美国视觉服务处理，消息可回看原图。影响 C02/C04/C05/C06，窄窗口保持相同阅读层次。

用户已要求实施本方案。C10 使用右侧纸色列表与详情：技能正文可审阅，应用显示原生测试结果，工具按助理分配。C09 使用单一大工作表面呈现真实专用浏览器帧，保留接管/交还及断线状态；电脑沿用原生控制租约。P01 书房人物与持续语音保持；本轮仅打开设置暂停收音，工作面保持倾听。C05 扩展真实 DOCX/XLSX 文件：文档使用阅读页，表格使用有表头的可滚动数据区，下载来自实际文件哈希。P05 例行工作展示原生 schedule/run 状态与关联工作，既有提醒继续保留，不显示合成进度。MCP Apps 标准资源桥接单独验收，普通 HTML 预览不冒称完整 MCP Apps Host。

P05 已补顶部“目标”入口；880px 以内的阅读面默认显示实际成员回复、目标结果与文件，digest/已处理审批/活动放在“查看工具过程”。单个目标可暂停、补充后继续同一原生团队。C10 有 IMAP、Google、Microsoft 本地账号表单、真实测试状态与重新授权入口；没有真实账号时显示空状态。手机宽度 390px 下隐藏低优先级书房标题，顶栏入口不换行挤压；分类自然换行，主要正文独立滚动。上一阶段截图与99项检查见[原生能力验收](../docs/原生能力与应用接入验收_v1.0.md)；最新104项、附件、并行沟通与视觉服务失败见[当前验收](../docs/持续沟通与图片识别验收_v1.0.md)。

## 页面模式：复用、扩展和新增

| 模式 | 决策与原因 | 页面和主要动作 |
|---|---|---|
| P01 陪伴 | 复用人物、书房、底部持续语音入口；扩展轻量主对话 | 人物维持视觉中心；右上显示近期气泡，可展开历史。侧边只留一条当前工作提示和待处理数量。点击人物状态可查看实际活动 |
| P02 工作 | 扩展为可调整宽度的工作区域；现有窄阅读窗不能展示真实电脑、表格或 diff | 从对话中的任务摘要打开，顶部显示任务与负责助理。按内容打开“电脑 / 成果 / 过程”，不用所有任务统一套三层嵌套卡。人物留在场景可见区，工作区展开只由用户触发 |
| P03 纯净 | 复用 | 隐藏普通工作信息，持续语音和退出入口保留。需要用户介入只给一条不消失的轻提示，点击回到具体任务 |
| P04 助理设置 | 复用抽屉，扩展技能和应用入口 | 模型、声音等技术设置移入这里；日常界面只显示连接异常等可行动状态。团队、技能、应用作为设置内独立列表，不增加常驻悬浮卡 |
| P05 目标与工作索引 | 新模式：长期目标和多个任务没有等价入口 | 一个可收起的导航入口，列表包含“需要我、进行中、成果、例行工作”。目标可打开计划、当前步骤和下次运行；未接通时明确空状态，不填演示进度 |

“人物变成小窗 / 场景变暗”的具体展开样式尚未定稿；以批准形象和面部可见为前提做原型评审，不直接更换用户已认可的场景。窄窗口只展示当前主要内容，按返回回到主对话；不承诺本轮已完成原生移动端。

## 组件模式

扩展 C02：消息按一次表达分组，单条回复有正文、引用、工具结果与任务链接这些内容类型；用户与助理的气泡有稳定节奏。流式消息延续同一气泡，较长正文可展开，后台任务回报带实际作者与关联任务。不会因人物、聊天和工作切换复制一份会话。

扩展 C03：团队从真实成员动态加载；新增成员以普通成员行出现，显示岗位、当前工作和可打开入口。支持新建、查看职责、重命名、归档恢复的确定性控件，具体动作使用原生 API。初始只有两名小助理时就只显示真实两名。

扩展 C05：成果按类型呈现。文档显示实际标题、摘要和阅读/下载；表格显示列与数据；网页显示真实预览；代码显示文件树、diff 和真实检查结果；没有对应成果时显示助理回复，而不是伪造文件。重复调用日志折叠，错误、需要输入和最终产物保持可见。

扩展 C06：确认界面明确对象、动作和结果，点击后形成可回看的回执；已过期、提交中、拒绝、冲突均有状态。相同任务不要反复弹新的全局卡片。代码实现不读取模型正文来决定批准了什么。

新增 C09 电脑视图：连接状态、实际屏幕、当前动作摘要、暂停/继续、接管/交还、关闭查看。数据来自原生帧与控制租约；断开时冻结并标明旧帧，不循环播放演示视频。关闭视图只停止观看，是否停止操作由单独按钮控制。

新增 C10 技能与应用列表：技能名称/用途/来源/启用/待审版本；应用名称/账户/已连接状态/可用工具。列表→详情→操作回执，不使用“已连接”假按钮。导入后的工具和权限必须来自真实服务器目录。

## 交互规则与内容

- 输入里保留附件和明确的语音/打字切换。对话可以自然安排工作，不强制每次手动切“安排任务”模式。连续语音的两秒停顿和终态归属继续沿用。
- 派工后气泡用一句话说明负责人和下一步，随后显示可打开的任务摘要；用户可继续对话。需要补充信息回到这个任务的问题，而不是中断其他话题。
- 电脑进行登录、选择或确认时，在相同任务显示“需要你接手”；接手后任务暂停鼠标输入，交还后继续，不能人与 bot 同时操作。
- 结果展示实际正文或可操作对象。示例：“资料已整理，包含 6 个来源”后面是文档与引用入口；无来源数据时不显示数量。
- loading 保留已有气泡和任务，不闪空；失败定位到具体工具/任务，可修改要求后继续，不默认重放已经成功的写入；离线保留草稿与历史；没有能力时提供确切配置入口；待审批与忙碌分开。
- 需要新增话题时使用原生 thread，返回主对话保持阅读位置、草稿和语音状态。记录到达时，用户正在看历史只显示新消息提示。
- 键盘、焦点恢复、IME 输入、减少动态效果与原有可访问规则继续适用。自动动画不能滚走用户正在读的正文。

## 视觉与 token 约束

沿用已有 primitive → semantic → component 的颜色体系，本轮没有全局改 token。下一原型的边界：一个主要工作表面，气泡、列表行、阅读页、代码区和电脑屏幕各有结构；减少一层套一层的圆角容器、悬浮胶囊与同色大面板。暖色用于场景和少量强调，正文保持足够对比，不能把所有状态都染成浅绿。

正文以 15–16px 的可读层级校样，任务名和产物标题较高一级，来源/时间为次级；正文行宽按阅读控制，长代码与表格局部横向滚动。圆角、间距和阴影引用现有 semantic/component token；如需调整，先标明影响 P01/P02/P04 再修改，不继续叠加覆盖样式表。

过渡只表达区域展开、接管和完成，初始建议 180–220ms，并支持 reduced motion。字符的呼吸、口型等仍按独立人物驱动方案验证，不能用 CSS 摇晃冒充状态感知。

## 初始研究的原型与质量门（历史草案）

下一原型至少包含：从一句话创建新助理并派工；技能候选→启用→复用；电脑操作→接管→恢复；文档/网页/表格/diff 结果→继续提问；两个并行任务中的一个出错但聊天继续。数据用固定、显式标注的合成场景，不能混进用户真实会话。

本轮通过的是事实、参考、复用选择和状态规则的文档自检。运行态仍按上一轮 UI 文件；扩展没有实现，未作像素级完整竞品体验或真人验收。全屏、125% 缩放、窄窗口焦点与真实 Computer Use 必须在实际实现后检查。开放问题：工作区展开几何、具体成果组件样式、长期目标数据模型与“Chávez”的确切含义。
